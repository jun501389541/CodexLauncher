# AI Usage Bridge 阶段三实施记录

日期：2026-10-02（Asia/Hong_Kong）。按补充规格和阶段三计划实现配对与设备授权。用户持续授权开发；当前交付为 App 内部服务模块和合成验证，桌面操作界面在阶段五接入。

## 已实现

- `BridgePairingService`：256 位一次性邀请码、两分钟邀请、原子消费与并发重放拒绝；独立 256 位会话令牌、五分钟审批会话、本机批准/拒绝接缝。每来源五次/分钟，返回 429 和 Retry-After；最多二十个待审批申请、二十台授权设备。
- 电脑批准后经 HTTPS 独立交付长期设备令牌。两分钟内允许重试领取同一令牌；ACK 幂等，首次有效设备认证同样完成交付。完成后状态查询不再返回明文令牌。
- 每秒回收过期会话，所有 HTTP 请求在认证前再次检查到期。未完成交付超时撤销；停止 HTTPS Host 清除邀请与会话、撤销未完成设备。清理或交付持久化失败时 HTTP 返回服务不可用，不继续处理受保护请求。
- `BridgeDeviceStore`：只持久化 SHA-256 令牌哈希与设备元数据，使用当前用户 DPAPI 和既有目录 ACL/原子文件边界。增加持久化交付完成标记；启动时丢弃未完成交付，覆盖进程崩溃恢复。设备列表、单台撤销和全部撤销通过本地服务接缝提供，撤销后 bearer 立即失效。
- `BridgeAccountGrantRepository`：DPAPI 持久化当前匿名账号与明确批准的设备。相同账号跨重启保留授权；任何身份变化清除授权，切回旧账号也须本机重新确认。不能识别账号时不创建账号授权。
- Kestrel 接入 POST pair、GET pair status、POST ACK。会话 bearer 与设备 bearer 分开验证；不存在远程批准或远程账号授权端点。公开配对页立即清除邀请 fragment，显著提示通过浏览器证书查看器人工核对 TLS 证书。
- 更新 OpenAPI 与接入说明：补全配对错误码及服务未启用响应；过期会话采用 HTTP 410，200 状态枚举不再包含 Expired。
