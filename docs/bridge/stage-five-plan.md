# 阶段五实施细化

按已批准规格开发，不改变实际用户启动项或启用真实账户共享。

1. D-22 优先于旧计划：主窗口增加 AI 额度桥分区，托盘只恢复主窗；二维码在分区展示。沿用递归 UiTheme.Style、DPI 和主窗滚动布局。
2. 开机命令加 --background，识别已登记可执行路径（兼容旧无参值）。单实例使用独立后台信号，不唤醒窗口；既有实例只尝试启用已配置网卡上的桥。背景实例仅启动设置允许的桥和额度，不运行代理诊断或 Codex 激活。
3. BridgeRuntime 拥有身份、设备、授权及 LAN；额度仍由 MainForm 单一所有者提供，即使监测关闭也创建无 provider 的共享协调器。选择网卡与账号昵称保存在独立 DPAPI 文件，不扩展明文 settings 的敏感字段。
4. 主窗提供开关/网卡/端口/状态、二维码倒计时、待审批与拒绝、设备重命名/撤销/全部撤销、账号昵称与逐设备重新授权、连接及复制防火墙命令。重要授权/撤销按钮显示明确本机确认。
5. 关窗隐藏继续共享；显式退出和系统退出先停 LAN 再释放桥存储和额度查询。二维码隐藏/失效/重绑后清除控件里的邀请数据。不将二维码写文件或日志。
6. 用合成运行时与实际回环 TLS 证明 UI 数据边界及清理，默认关闭、不写真实 Run 键；在 STA 验证主题和缩放布局。独立只读审查一次、修复重要项，全回归、报告和索引。

Ruling：D-9 设置仅开关/端口，网卡选择另存 DPAPI；没有合法已选网卡时后台信号不自动选网卡，显示等待选择。代价：首次启用须在主窗口选择网卡。
Ruling：后台启动仅桥和额度，初次恢复主窗再加载常规代理/诊断监测。代价：隐藏启动期间不跑原窗口诊断。
Ruling：保留 mDNS 门禁与实机验收，合成 UI 验证不解除第四阶段阻塞。
