## 1. 目标、范围与案例依据

### 1.1 目标

在现有 Windows Codex 启动器中增加 **AI Usage Bridge**，让同一局域网内的手机通过配对读取电脑上的 Codex 额度和重置时间。

Bridge 作为启动器内的独立模块运行，共享现有额度查询、缓存、托盘和退出流程。

### 1.2 已确认范围与全局约束

- **只开发启动器端**，交付手机端对接协议、示例和测试客户端。
- 第一版仅提供**当前登录账号的额度与重置时间**。
- 包含扫码配对、电脑确认、授权设备管理和局域网自动发现。
- 切换 Codex 账号后，需要电脑重新确认共享授权；设备无需重新扫码。
- 手机显示用户自定义昵称，默认“Codex账号”，不接收真实邮箱或平台账号 ID。
- 提供“登录 Windows 后自动启动”开关，默认关闭；开启后启动器进入托盘，不自动启动 Codex。
- 不开发外网访问、Android App、模型转发、远程关闭 Codex或代理控制。
- 保持 .NET 10 WinForms，不引入第三方 UI 框架。
- 不读取、复制或导出 Codex 认证文件，不发送模型验证请求。
- 不自动修改全局代理、TUN、防火墙或系统网络配置；防火墙辅助和开机启动必须由用户主动操作。
- 不影响现有启动、关闭、网络监测、悬浮窗、代理变量恢复、固定入口和额度功能。

## 2. 用户流程与数据行为

### 2.1 首次连接

1. 用户在启动器打开“手机额度共享”。
2. 选择连接手机的局域网网卡，开启 Bridge。
3. 点击“添加设备”，生成两分钟有效二维码。
4. 手机扫描二维码，核对 HTTPS 证书指纹并提交配对申请。
5. 电脑显示设备名称，用户选择允许或拒绝。
6. 允许后，手机取得独立设备凭据，可以读取已授权账号的额度。
7. 后续通过 Bridge ID 和自动发现重新定位电脑，无需固定 IP。

第一版不开发手机界面，以上流程通过交付的协议测试客户端验证。

### 2.2 日常读取

- 手机读取 Bridge 内存快照，普通 GET 请求不触发上游查询。
- 额度仍由现有服务每5分钟更新。
- 手机可申请刷新，使用与主窗口共享的调度和节流。
- 失败保留同账号的最后成功数据，并返回原始采集时间、陈旧标记和错误类别。
- 重置时间到达后等待实际查询确认，不自动把剩余比例填为100%。
- 电脑关机、睡眠或退出启动器后，Bridge 离线；客户端根据连接失败展示离线并保留自己的旧快照。

### 2.3 账号与设备授权

- 配对授权和 Codex 登录分别管理。
- Codex 登录失效不删除设备配对。
- 账号切换立即停止向设备提供新账号数据。
- 电脑端提供“允许这些设备查看当前账号”，确认后恢复读取。
- 切回以前已授权的账号，可以恢复其既有授权。
- 账号身份无法确定时返回不可用状态，不把旧账号数字挂到未知账号。
- 支持设备重命名、单设备撤销和撤销全部设备。
- 授权按设备与账号绑定，昵称变化不改变账号身份。

## 3. 技术架构与协议

### 3.1 模块与生命周期

新增 `CodexLauncher.Bridge` 类库，目标为 `net10.0-windows`，使用 ASP.NET Core Kestrel；保留 WinForms 主界面。

建立启动器后台服务容器，统一持有：

- 一个额度提供者。
- 一个共享刷新调度器。
- 一个 Bridge 服务。
- 一个发现服务及设备授权仓库。

主窗口、托盘、悬浮窗和 Bridge 订阅同一份额度结果。

HTTP 请求取消只取消该客户端等待，不取消其他设备或主界面共享的上游查询。上游查询由启动器生命周期令牌与现有请求超时控制。

默认行为：

- Bridge 默认关闭；用户开启后保存设置。
- 主窗口关闭继续后台运行。
- 停止 Bridge 关闭监听、发现和未完成配对，保留设备授权。
- 退出启动器释放 Bridge 和额度服务。
- 不安装 Windows 服务，不启动第二个额度查询守护程序。
- 开启 Bridge 需要额度监测开启；若用户关闭额度监测，Bridge停止读取并返回明确不可用状态，不悄悄重开该设置。

### 3.2 网络与发现

- 第一版支持用户选择的一个 IPv4 私有局域网网卡。
- 不默认绑定所有网卡；排除 TUN、回环和虚拟网卡作为手机连接候选。
- 默认 HTTPS 端口 `43189`，支持修改；端口占用时显示原因，不结束占用进程。
- 不复用固定代理入口 `7896` 或 Mihomo 控制端口 `9098`。
- 使用 DNS-SD 服务类型 `_aiusage._tcp.local`。
- 发现广播仅包含 Bridge ID、协议版本和服务定位信息，不含账号、额度或凭据。
- IP 变化后重新绑定原网卡的新地址并更新广播；网卡或私有网络条件失效时暂停共享。
- 多播被网络屏蔽时，保留手动填写地址及重新扫码的连接方式。

mDNS 使用 [Makaretu.Dns.Multicast](https://github.com/richardschneider/net-mdns)，实施第一阶段验证指定网卡广播、Windows 兼容性并锁定依赖版本。二维码使用 [QRCoder](https://github.com/Shane32/QRCoder)。如指定网卡隔离测试不能通过，应记录依赖阻塞并修正适配器，不能通过广播到全部网卡规避要求。

防火墙设置提供独立操作入口：用户主动执行后，仅为当前程序创建 Private 网络、LocalSubnet 来源及所需端口规则；不关闭防火墙、不开放 Public 网络。权限或策略限制时显示手动操作指引。规则以本软件固定前缀标识，只维护本软件创建的规则。

### 3.3 HTTPS、身份与配对

- 创建持久化随机 `bridgeId` 和专用自签名服务器证书。
- 二维码包含：协议版本、Bridge ID、连接地址、证书 SHA-256 指纹、一次性配对凭据和失效时间。
- 手机必须在发送任何凭据前核对实际 TLS 证书指纹。
- 自动发现不能替换已经绑定的证书指纹。
- 不把自签名证书安装到系统受信任根证书库。
- 证书私钥和账号映射密钥使用 Windows 当前用户 DPAPI 保护。
- 永久设备凭据使用至少256位随机值；服务器仅保存验证哈希。
- 配对凭据只在内存保存，两分钟有效，首次申请后原子占用。
- 配对申请五分钟内未得到电脑确认则失效。
- 设备凭据在确认后通过 HTTPS 交付，允许在短期交付窗口内重试；完成确认后清除内存中的明文。
- 拒绝、过期、停止服务和重置身份均使未完成配对失效。
- 重置 Bridge 身份同时撤销所有设备，明确提示需要重新扫码。

额度 API 仅接受设备凭据；配对凭据不能读取额度。设备管理只在电脑界面执行。

配对状态固定为：`Invited → PendingApproval → Approved → Delivered`，拒绝和过期进入终态。申请占用邀请后返回随机配对会话凭据；后续查询只使用该凭据。批准后设备凭据明文只在内存保留两分钟；ACK或首次正常设备认证后清除。交付超时撤销该未完成设备凭据，需要重新配对。服务重启不恢复未完成配对。

授权与身份记录保存在 `%LOCALAPPDATA%\CodexLauncher\bridge`，原子写入，限制到当前用户访问；设备授权仓库只保存凭据哈希、设备ID/名称、账号授权与时间信息，不保存Codex令牌。

### 3.4 API 与对外数据

全部接口位于 `/v1/`。除健康检查与配对申请外，必须认证；配对状态和ACK使用专用配对会话凭据。

| 接口 | 用途 |
| --- | --- |
| `GET /v1/health` | 返回 Bridge ID、版本和服务状态，不包含账号数据 |
| `POST /v1/pair` | 用一次性凭据申请配对 |
| `GET /v1/pair/{id}` | 用专用配对会话凭据查询确认状态和领取设备凭据 |
| `POST /v1/pair/{id}/ack` | 确认设备凭据已收到 |
| `GET /v1/providers` | 返回首版支持的 Codex 与能力信息 |
| `GET /v1/accounts` | 返回该设备获授权的当前账号昵称与匿名 ID |
| `GET /v1/accounts/{id}/usage` | 读取缓存额度 |
| `POST /v1/accounts/{id}/refresh` | 请求共享刷新，返回202及状态 |

设备认证使用 `Authorization: Bearer …`；令牌不能放在请求 URL。

对外建立独立 `UsageResult` DTO，不直接序列化现有 `QuotaSnapshot`：

```text
schemaVersion
bridgeId
providerId
accountId
displayName
status
quotaWindows[]
updatedAt
dataTimestamp
sourceTimestamp
isStale
errorCode
```

额度窗口包含：

```text
id
label
usedPercent
remainingPercent
windowMinutes
resetAt
```

规范：

- `accountId` 为 Bridge 本地匿名 ID，不返回邮箱、平台账号 ID、用户目录或原始认证信息。
- 窗口 ID 包含额度桶和窗口身份，避免多个 primary/secondary 冲突。
- 不写死五小时或每周，按实际窗口长度展示。
- 缺失值为 `null`，不伪造为0。
- 时间统一使用 UTC RFC3339；客户端转换本地显示。
- `dataTimestamp` 为额度成功采集时间，`updatedAt` 为 Bridge 状态更新时间；`sourceTimestamp` 未提供时为 `null`。
- `status` 使用 `OK`、`STALE`、`AUTH_REQUIRED`、`NO_DATA`、`NETWORK_ERROR`、`UNSUPPORTED`。
- 设备无效返回401；账号未授权返回403；账号切换返回409；请求过频返回429及 `Retry-After`。
- 额度 GET 不隐式刷新；刷新全局至少间隔10秒，并共享在途任务。
- 请求体上限16KB；设备最多20个；每设备读取最多每分钟60次；配对申请每来源最多每分钟5次。
- 不允许跨站网页访问，不启用宽松 CORS；不开放文件读取、命令执行或 App Server 原始代理。
- 日志只记录规范化状态与错误类别，不记录请求体、认证头、二维码内容和额度原始响应。

### 3.5 需要新增或调整的接口

- `BridgeHost.StartAsync / StopAsync`：服务生命周期。
- `BridgePairingService`：一次性邀请、申请、确认和交付。
- `BridgeDeviceStore`：设备认证与撤销。
- `BridgeAccountGrantStore`：匿名账号身份及设备授权。
- `BridgeDiscoveryService`：网卡范围内的 DNS-SD。
- `SharedQuotaCoordinator`：缓存、统一刷新、取消隔离与账号版本控制。
- 为现有额度提供者补充内部账号身份与切换事件；不将身份字段公开到网络 DTO。

账号匿名映射使用持久化本地秘密对内部账号身份做HMAC。内部身份包含认证方式及可确认的账号/工作区标识；使用现有账号比较逻辑并加强未知身份处理。昵称不参与身份计算。无法可靠区分当前账号或工作区时不自动授予数据访问。

## 5. 验收标准与 Agent 交付要求

### 5.1 Review Focus 与必测场景

优先复查：跨账号数据泄漏、共享查询取消传播、配对凭据重放、发现消息替换证书信任、网络配置变化后错误暴露服务。这五项均须在对应阶段有明确测试。

- 正常额度、多个窗口、缺失值、重置到点、数据过期和查询失败。
- 多设备读取不重复轮询上游；客户端断开不取消共享查询。
- 配对过期、重复申请、电脑拒绝、设备撤销、Bridge重置。
- 账号切换、退出登录、身份未知和不同工作区，均不泄漏旧账号或未授权账号数据。
- 错误证书指纹、伪造发现消息、无令牌、错误令牌和限流。
- Party/Verge TUN开启时，Bridge仍绑定用户选择的真实局域网网卡。
- IP变化、网卡断开、多播受限、防火墙限制、休眠恢复。
- 主窗隐藏、重复启动、开机启动、显式退出和端口占用。
- 浅深主题与100%—200% DPI下二维码、设备列表和操作可用。
- 原有启动、关闭、代理入口、监测、悬浮窗与额度功能回归通过。

### 5.2 最终交付物

1. 含 Bridge 的自包含 Windows 程序。
2. 完整 `/v1/` 对接协议、OpenAPI、JSON Schema和示例。
3. 支持发现、指纹校验、配对、读取、刷新和撤销验证的协议测试客户端。
4. 用户使用说明、排障说明、构建命令与依赖许可证清单。
5. 单元测试、HTTP集成测试、局域网实测记录与发行哈希。

Windows端验收以协议客户端和第二台局域网设备为准。Android App与Widget联调留给手机端开发阶段，报告中明确标为未验证。
