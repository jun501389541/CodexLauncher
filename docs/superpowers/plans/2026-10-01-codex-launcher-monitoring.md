# Codex 启动器：免费监测、主题、悬浮窗与额度查询实施计划

> **状态：待用户审查。** 本轮仅生成计划，不实施软件功能、不发送模型请求、不关闭 Codex。
>
> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task after user approval. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal：** 在不额外发送模型请求的前提下，提供可理解的 Codex 网络状态、额度与重置时间，并改善夜间界面、关闭操作和后台查看体验。

**Architecture：** 保留启动前诊断，独立增加运行期监测与额度查询服务。主窗口、托盘和悬浮窗共享快照；网络探测、诊断事件和额度查询分别采集，避免将额度不足误报为断网。

**Tech Stack：** .NET 10、Windows 10/11、WinForms、自包含 win-x64；诊断数据库使用 Microsoft.Data.Sqlite，只读访问；额度使用配套 Codex CLI 的 App Server JSON-RPC stdio 接口。

**Spec：** 本文第1—7节为审查规格，第8—10节为实施任务、验证与交付要求。

**日期：** 2026-10-01。

## 3. 免费检测与运行状态

### 3.1 采集规则

- 启动前继续比较现有系统默认网络与配置代理；保留原有8秒超时和6秒慢响应规则。
- Codex 运行时，只周期探测正在使用或可确认的线路，每5秒一轮，单次请求最长3秒。
- HTTPS 只读取响应头，不附加账号凭据、不读取响应正文；HTTP 2xx、401、403、404、5xx 都计为“收到回应”。
- HTTP 响应只代表传输线路可达，不代表登录、模型服务或 WebSocket 一定正常；实际网络诊断事件用于补充判断。
- 网络计时采用单调时钟；界面检测时间、重置日期使用系统本地时间。
- 检测是单任务执行。手动刷新与定时刷新合并；线路变化取消旧任务，丢弃旧线路的迟到结果。

### 3.2 状态转换

“正常样本”指收到 HTTPS 回应且耗时低于2000ms；“慢样本”指收到回应但耗时达到2000ms；“失败样本”指 DNS、连接拒绝、TLS 错误或3秒超时。

| 状态 | 条件 | 主文案 |
| --- | --- | --- |
| 蓝灰 | 当前线路首次采样完成前 | 正在检测 |
| 黄色 | 首次采样后尚未累计3次正常；任一次慢样本或失败样本；已确认的短暂重连；线路发生变化 | 正在确认线路／网络波动 |
| 绿色 | 连续3次正常样本且没有未恢复的实际网络故障 | 线路稳定 |
| 红色 | 连续3次失败样本；或当前桌面实例的网络重连故障持续超过20秒；或双 TUN 冲突 | 连接异常，影响使用 |
| 灰色 | Codex 未运行，仅用于悬浮窗与托盘 | Codex 未启动 |

- 慢样本或失败样本都会清零连续正常计数；收到任意 HTTP 回应清零连续失败计数。
- 红色或黄色恢复绿色，须连续3次正常样本；实际重连异常还须有对应恢复事件。若诊断源失效，则移除无法继续确认的事件状态，改为线路检测并显示证据降级说明。
- 在固定5秒周期、请求最多3秒且无调度停顿时，持续断网最迟约18秒转红；系统睡眠、卡顿和恢复另行处理。
- 长时间生成、等待审批、用户取消、工具错误、没有日志更新，不计为网络故障。
- 额度不足和未登录使用独立黄色业务提醒，网络灯仍按网络证据判断。
- 备用线路失败不影响当前可用线路；不通过扫描失败数量决定红灯。
- 每轮检查维持上一状态，小型刷新提示代替全卡变蓝，避免颜色频繁闪烁。
- 系统恢复后立即检测；超过15秒没有有效采样时显示黄色“状态未更新”，不把旧绿灯当作实时结果。

### 3.3 线路归属

- 启动器启动 Codex 时记录启动路径及线路指纹：路径类型、代理入口、固定入口上游与端口、TUN 状态。
- Party/Verge 端口、入口上游或 TUN 变化后立即重新采样，清除旧绿色依据。
- 改变启动器配置不等于运行中的 Codex 已切换路径。需要重新启动才能生效的配置显示提示。
- 外部启动的 Codex 显示“实际启动线路未确认”；探测系统默认网络时明确标注，不能假装已确认桌面流量归属。

### 3.4 本机诊断事件

- 对本机诊断库建立只读、增量适配器；从监测开始后的记录读取，不回扫历史。
- 使用事件来源、结构字段和桌面实例关联白名单，仅提取时间、网络成功、网络失败、重连与恢复类别。
- 不全文搜索“timeout”“Reconnecting”，防止把用户文字、工具输出或历史故障误判为当前异常。
- 本地 IPC 成功、`turn/completed` 本身及 HTTP 403 均不能被单独解释为模型任务成功。
- 未能关联到当前桌面实例的事件丢弃；不将其他 CLI 或另一桌面实例的错误合并进来。
- 诊断库缺失、锁定、字段变化或事件格式不支持时，退回网络探测，并显示“仅依据线路检测”。
- 诊断格式不是稳定公开接口。实施时先使用当前版本的脱敏样本验证解析和归属；不满足条件则默认禁用该版本的事件适配器。
- 只保存规范化状态和错误类别，不持久化读取到的原文；不扫描 `sessions` 或 `archived_sessions` 对话文件。

## 4. 主题、启动与关闭操作

### 4.1 完整主题

- 新增“跟随系统／浅色／深色”设置，默认跟随系统；响应 Windows 主题变化。
- 主窗口、表格、按钮、弹窗、右键菜单、托盘菜单及悬浮窗统一使用主题颜色。
- 明确控制按钮正常、悬停、按下、禁用和键盘焦点状态的文字与背景，修复启动按钮不可读问题。
- 普通文字以至少4.5:1对比度为设计目标；禁用操作也须可读，并附带具体原因。
- Windows 高对比度模式优先采用系统颜色。
- 保留 Codex MSIX 图标和第三方助手说明；图标不可读时使用中性备用图标。

### 4.2 关闭 Codex

- “关闭 Codex”紧邻“启动 Codex”；未运行时禁用，身份无法确认时展示原因。
- 依据安装包身份、规范化可执行文件路径和进程启动时间确认桌面进程，路径匹配包含目录边界。
- 向已确认桌面窗口请求正常关闭，不通过进程名批量结束。
- 等待8秒未退出时显示“继续等待／取消／强制关闭”；继续等待追加8秒，取消不做后续结束动作。
- 强退前明确提示“可能中断正在执行的任务”，仅确认后执行。执行前再次核对 PID、启动时间和身份，避免进程编号复用。
- 强退仅作用于已确认属于目标实例的 Codex 进程及其受验证子进程，不结束其他 CLI、Party、Verge 或固定入口。
- 未知身份、权限不足或关闭失败时给出原因，不自动提权；网络监测不阻塞关闭按钮。
- 关闭完成后主窗口回到启动前诊断，悬浮窗变灰。

- 悬浮窗显示圆点＋“稳定／波动／连接异常／未启动”，同时使用符号和文字，不仅依赖颜色。

- 鼠标停留显示线路、Party/Verge、端口、耗时、更新时间、原因、建议及额度摘要。
- 双击恢复主窗口；右键提供打开主窗口、隐藏悬浮窗和退出启动器。
- 主窗口最小化或点击关闭均继续后台监测；首次关闭时用托盘提示说明恢复与退出方式。

- 防止重复启动多个后台监测实例；再次打开启动器时激活已有主窗口。

## 6. 额度与重置时间

### 6.1 接口与账号

使用官方 App Server 接口：

- `account/read`：读取当前认证方式和账号信息，参数 `refreshToken: false`。
- `account/rateLimits/read`：读取额度窗口、已用百分比和重置时间。
- `account/rateLimits/updated`：处理该查询连接收到的额度更新通知；不假设另一桌面进程的所有用量变化都会主动推送。

通过已定位的配套 Codex CLI 启动启动器自有 App Server，使用 stdio；执行初始化握手后只调用上述只读账号接口，不开放网络监听，不启动对话。

凭据由 Codex 自身处理，启动器不读取或复制 `auth.json`。无法复用既有登录时显示“需要先登录配套 CLI”，不自动启动登录、退出登录或强制刷新认证。

查询展示“额度查询账号”与计划类型。无法确认它与桌面当前账号一致时明确提示“请核对桌面账号”，不标为已确认一致。账号切换时立即清除上个账号的额度缓存。

### 6.2 展示与刷新

- 主界面新增独立“额度与重置时间”卡片；查询默认启用，CLI 不存在或不支持时展示“暂不可用”。
- 优先使用 `rateLimitsByLimitId`，没有该字段时兼容 `rateLimits`；动态显示多个桶和 primary/secondary 窗口。
- 显示窗口长度、剩余百分比、重置日期时间、倒计时、查询账号、数据更新时间。
- 剩余百分比计算为 `clamp(100 - usedPercent, 0, 100)`；缺失或无效数据为“暂不可用”，不是0%。
- 不把示例窗口写死为“五小时／每周”；仅当返回长度匹配时使用对应易懂名称。
- `resetsAt` 按 Unix 秒转换为本地日期时间；到点触发一次重新查询。在新结果返回前显示“等待确认重置”，不自行填成100%。
- 默认每5分钟刷新，提供手动刷新；同一时间只允许一个额度查询，手动刷新间隔至少10秒。
- 每次查询最多10秒。失败后按5、10、20、30分钟逐步退避；成功恢复5分钟周期，手动成功也恢复周期。
- 查询失败保留当前账号的上次结果，显示“数据未更新”及时间；超过10分钟标记“数据可能已过期”。重置倒计时到点不绕过失败退避无限重试。
- 剩余不高于20%时额度卡黄色提醒；不高于5%或接口确认受限时显示更突出提醒。未提供余额字段时不推算剩余请求数或 Token 数。
- 首版只做界面提醒，不发送邮件、不自动购买额度、不调用额度重置兑换接口。
- API Key 登录显示“此登录方式不提供订阅额度”；不假装返回API账户余额。

额度快照仅在内存保存，配置和日志不存账号邮箱、完整账号响应或凭据。退出后下次重新查询。

## 7. 公共接口与职责划分

保留现有项目分层，不把采集、状态计算和关闭操作全部堆入 `MainForm`。

| 单元 | 核心接口或类型 | 职责 |
| --- | --- | --- |
| 运行期模型 | `RuntimeHealthInput`、`RuntimeHealthSnapshot`、`RuntimeHealthEvaluator.Evaluate(RuntimeHealthInput)` | 纯函数计算状态、原因和建议，输入包括计数、事件、线路、采样新鲜度 |
| 监测服务 | `RuntimeMonitor.Start()`、`RequestRefresh()`、`StopAsync(CancellationToken)`；`SnapshotChanged`事件 | 单任务采样、取消、周期、线路版本与统一快照 |
| 诊断源 | `ICodexDiagnosticSource.ReadSinceAsync(DiagnosticCursor, CodexInstance, CancellationToken)` | 返回规范化事件、游标和来源可用性，不返回日志原文给UI |
| 桌面生命周期 | `ICodexDesktopController.DiscoverAsync(CancellationToken)`、`RequestCloseAsync(CodexInstance, CancellationToken)`、`ForceCloseAsync(CodexInstance, CancellationToken)` | 身份发现、正常关闭与受控强退 |
| 额度提供者 | `ICodexQuotaProvider.ReadAsync(CancellationToken)`；`QuotaChanged`事件 | 封装版本兼容、初始化、只读账号请求与规范化快照 |
| 额度模型 | `QuotaSnapshot`、`QuotaBucket`、`QuotaWindow` | 账号归属、可用/不支持/未登录/失败状态、窗口、重置时间和新鲜度 |
| 主题 | `ThemeMode`、主题调色板与变更事件 | 系统主题、手动主题和所有控件刷新 |
| 悬浮窗 | `FloatingStatusForm` | 渲染共享状态、拖动、提示、主窗恢复；不采集网络 |

类型补充：`CodexInstance`携带可验证进程身份；`DiagnosticCursor`仅是增量位置；`RuntimeHealthSnapshot`携带证据来源和实际线路是否确认。现有 `AccessHealthSnapshot`仍用于启动前，不混入账号额度字段。

配置扩展：`ThemeMode`、`FloatingWindowEnabled`、悬浮窗位置和`QuotaMonitoringEnabled`。旧字段保留，新增字段缺失时使用本计划默认值；配置不能保存时维持本次会话设置并明确提示。

诊断服务与额度服务均提供可注入的时钟、探测器及模拟输入，支持不访问真实账号的测试。

## 10. Review Focus、默认行为与资料

优先复查以下五类问题，其测试分别归属任务1—5：

1. 用户内容或其他实例日志触发假红灯：必须被排除。
2. 新线路到来后旧请求覆盖新状态：必须丢弃旧结果。
3. 关闭误伤其他进程或任务：正常退出优先，身份重新确认，强退须明确确认。
4. 主窗关闭后用户无法找回软件或程序无法退出：托盘恢复与显式退出必须可用。
5. CLI账号与桌面账号不同，或额度数据过期：必须标明查询账号、更新时间和一致性未知。

其余默认行为：悬浮窗关闭、额度查询开启、主题跟随系统；不添加开机自启，不新增外部通知，不自动改变代理/TUN，不自动兑换额度重置。

协议兼容边界：官方文档证明额度接口及字段存在，不保证本机配套CLI版本支持，也不保证额度查询结果自动对应桌面当前账号。实施时验证接口支持与归属；不支持时明确回退为“暂不可用”。
